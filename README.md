# 이어집(가칭) – 부동산 상속·증여 관리 앱 소개 페이지

부동산 상속·증여를 앞둔 개인·가족을 위한 관리 앱(가칭)의 **제품 소개 웹페이지**입니다.
바이브코딩 입문자가 읽고 수정할 수 있도록 HTML/CSS/JavaScript 3개 파일로만 구성했습니다. (빌드 도구·설치 불필요)

> 서비스 이름 "이어집"은 **가칭**입니다. 화면의 숫자와 서류 목록은 **가상의 예시**이며, 법률·세무 자문이 아닙니다.

## 1. 주요 내용

| 섹션 | 설명 |
| --- | --- |
| 히어로 | 핵심 메시지, 버튼 2개, 앱 화면 미리보기(예시 데이터) |
| 기능 5가지 | 세무사 상담 / 취득비용·보유세 / 신탁 연계 / 공정증서 / 준비서류 안내·완료도 체크 |
| 서류 체크 체험 | 단계별 서류를 체크하면 완료도(%)가 바뀜. 체크 상태는 브라우저에 저장 |
| 진행 순서 · FAQ | 4단계 흐름, 자주 묻는 질문 |
| 대기자 등록 | 이메일 형식 검사까지만 동작 (**아직 서버에 저장되지 않음**) |
| 공통 | 라이트/다크 전환, 모바일 우선 반응형, 키보드 조작·접근성 고려 |

디자인은 [Resend](https://resend.com/)의 구성과 분위기(검정 배경, 얇은 테두리, 큰 제목, 파란 포인트, 코드 패널 느낌)를 참고했습니다. 로고·문구·이미지는 사용하지 않았습니다.

## 2. 실행 방법

1. `index.html`, `style.css`, `app.js` 세 파일을 **같은 폴더**에 둡니다.
2. `index.html`을 더블클릭해 브라우저에서 엽니다.

수정 후에는 브라우저에서 새로고침(F5)하면 바로 반영됩니다. 편집기는 VS Code를 권장하며, "Live Server" 확장을 쓰면 저장할 때마다 자동 새로고침됩니다.

## 3. 파일 구조

```text
.
├── index.html   # 페이지 내용(글, 섹션 구조)
├── style.css    # 디자인(색, 글자, 간격, 반응형)
├── app.js       # 동작(테마 전환, 서류 체크, 폼 검사)
└── README.md
```

## 4. 자주 하는 수정

| 하고 싶은 것 | 수정 위치 |
| --- | --- |
| 서비스 이름 변경 | `app.js` 맨 위 `BRAND_NAME`, `index.html`의 `<title>`·`description` |
| 색상 변경 | `style.css` 맨 위 `:root` 안의 `--accent` 등 (다크), `:root[data-theme="light"]` (라이트) |
| 문구 변경 | `index.html`에서 해당 문장 찾아 수정 |
| 체크리스트 서류 변경 | `app.js`의 `STAGES` 배열 (`[서류명, 설명]` 형식) |
| 카드 추가 | `index.html`의 `<article class="card">` 블록을 복사해 수정 |

실제 필요 서류는 사례마다 다르므로, `STAGES` 내용은 세무사·공증 기관 등 전문가 확인 후 확정하세요.

## 5. 동작 방식과 한계

- **테마·체크 상태**는 브라우저 `localStorage`에 저장됩니다. 브라우저를 바꾸거나 사이트 데이터를 지우면 초기화됩니다. 저장소가 막힌 환경에서도 오류 없이 동작하도록 처리했습니다.
- **대기자 등록 폼**은 이메일 형식만 검사하고 어디에도 전송하지 않습니다. 실제 수집은 아래 6번 단계가 필요합니다.
- 글꼴은 시스템 한글 글꼴을 사용합니다. (Pretendard가 설치된 환경에서는 자동 적용)

## 6. 다음 단계 (권장 순서)

1. **이름·문구 확정** 후 반영
2. **GitHub에 업로드:** 저장소 생성 → 파일 업로드. 개인정보·비밀 값은 올리지 않습니다.
3. **Vercel 배포:** GitHub 저장소를 연결하면 빌드 설정 없이 정적 사이트로 배포됩니다. (Framework: Other, Build Command/Output 비워둠)
4. **대기자 폼 연결:** Vercel Functions의 `/api/waitlist`와 Neon Postgres를 만들고, `app.js`의 폼 제출 부분을 `fetch("/api/waitlist", …)`로 교체합니다.
   - 서버에서 이메일 검증, 중복 방지, 요청량 제한을 적용합니다.
   - DB 주소 등 비밀 값은 Vercel 환경변수로만 관리하고, `.env.example`을 함께 둡니다.
   - 수집 목적·보관 기간을 알리는 개인정보 처리 안내 문구를 폼 근처에 추가합니다.
5. 앱 기능(상담, 서류 관리 등)이 커지면 React + Vite + TypeScript로 이전합니다.

## 7. 점검 목록

- [ ] 모바일(폭 390px 전후)에서 가로 스크롤이 없는가
- [ ] 라이트/다크 전환이 되고 글자가 잘 읽히는가
- [ ] 체크리스트를 체크하면 완료도가 바뀌고, 새로고침 후에도 유지되는가
- [ ] 잘못된 이메일 입력 시 안내 문구가 나오는가
- [ ] 키보드(Tab)만으로 메뉴·버튼·체크박스를 조작할 수 있는가
